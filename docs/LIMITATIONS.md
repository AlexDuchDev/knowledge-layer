# Known limitations and stubs (v1)

This list helps operators and **external contributors** set expectations. It complements [RELEASE_READINESS_AUDIT.md](./RELEASE_READINESS_AUDIT.md) and [SELF_HOSTED.md](./SELF_HOSTED.md). **Per-connector sync vs normalization depth:** [CONNECTOR_CAPABILITY_MATRIX.md](./CONNECTOR_CAPABILITY_MATRIX.md) (single table).

| Area | Status | Notes |
|------|--------|--------|
| **Knowledge job processors** | `weekly_digest`, `decision_extraction`, `planning_summary`, `stale_scan`, and `support_trends_extraction` are wired in the orchestrator (via `DigestRunner`) | Other `job_type` values are rejected on create (fail-closed) and/or **fail the run** with a clear error (no silent success). Treat non-digest processors as **early/experimental** versus production completeness goals. See [knowledge-jobs-engine.md](./knowledge-jobs-engine.md). |
| **Scheduled job tick** | `knowledge:scheduled_tick` enqueues due `scheduled` triggers (UTC minute, cron via `schedule_expr`) | Event/window/conditional triggers are not auto-fired by this tick. |
| **Connector artifact worker** | `ingestion:process_artifact` runs in [`connectorworker`](../apps/api/cmd/connectorworker/main.go) via `ProcessQueuedRawArtifact` | Supported queued normalization now covers **chat** (`telegram_update`, `slack_message`, `mattermost_post`), **docs/files** (`google_drive_file`, `notion_page`, `confluence_page`), and **calendar/meeting** (`google_calendar_event`, `fireflies_transcript`). Other raw `artifact_type` values still no-op to avoid Asynq retry storms until a normalizer exists. |
| **Blob / raw storage** | Default `blobstore.Nop` | Durable raw payload storage may require an S3/R2-style adapter for production retention goals. |
| **Metrics** | `GET /metrics` exposes Prometheus Go/process collectors plus `http_requests_total{method,route}` (Fiber route template) | Non-local requires `OPS_AUTH_TOKEN` bearer (same as pre-stub rules). |
| **OpenSearch (local compose)** | Security disabled | **Dev only**; production must use TLS + auth. |
| **Web shells** | Product: root `(dash)/` URLs are canonical | **Admin:** canonical **links** use `/control-plane/*` (legacy `/admin/*` redirects); many CP paths **rewrite** to existing dash pages until builders migrate — see [INFORMATION_ARCHITECTURE_V1.md](./INFORMATION_ARCHITECTURE_V1.md) and [ADMIN_UI_CONSOLIDATION_PLAN.md](./ADMIN_UI_CONSOLIDATION_PLAN.md). **`/app/*`:** deprecated for navigation; overlapping routes redirect to dash. |
| **Web UI honesty (local)** | Home + Search call out OpenSearch, job processors, and connector normalization limits | Primary nav is a single **Start** (Home, Search, Ask) + **Governance** + **Control plane** shortcuts + **Advanced** (settings, audit, ops). Control-plane setup now uses real onboarding sessions/preview/launch, but still depends on seeded templates/presets and the currently supported connector families/job types above. |
| **LLM transport (OpenAI / OpenRouter)** | Text embeddings; chat supports optional **vision + voice-in** on Ask | [`internal/llm`](../apps/api/internal/llm): embeddings are text-only. Ask may send multimodal **user** `content` (text + `image_url`; voice transcribed before retrieval). **Audio/TTS output** from the model is not implemented. See [CONFIG_ENV.md](./CONFIG_ENV.md) § “Multimodal Ask”. |
| **AI PrivacyGateway scope** | Ask + `POST /ai/*` helpers use sanitization / vault / rehydration | **Embeddings** and other non-chat OpenAI calls are **not** routed through the gateway by design for v1; rationale in [adr/0013-embeddings-privacy-boundary.md](./adr/0013-embeddings-privacy-boundary.md). Trust for vectors = **ingestion + domain ACL on chunks**, not placeholder redaction on the embed wire. |
| **Extracted meeting tasks** | Migrations `000037` + `000038` (tasks + Second Brain overlay tables) | **Product path (v1):** domain-scoped HTTP for list/create/patch/confirm/reject + web review at `/meeting-tasks`; optional LLM extraction job type is not wired yet — see [EXTRACTED_MEETING_TASKS.md](./EXTRACTED_MEETING_TASKS.md), [API_SURFACE_V1.md](./API_SURFACE_V1.md) (Second Brain). |
| **Staging / prod smoke (session)** | [`scripts/smoke-session.sh`](../scripts/smoke-session.sh) + [STAGING_SMOKE_TEST.md](./STAGING_SMOKE_TEST.md) | Requires `AUTH_MODE=session` and a user with password (bootstrap or admin-created); not a substitute for full E2E. |
| **Decision product surface** | `/decisions` rewrites to `/knowledge/decisions` (type-scoped browse via [INFORMATION_ARCHITECTURE_V1.md](./INFORMATION_ARCHITECTURE_V1.md)) | Dedicated decision-board lifecycle UI (draft → proposed → decided → revisited) is not in v1; planned for v1.1. The `decision_extraction` job is wired and produces decision entities. |
| **Project Memory** | Concept only | No implemented surface in v1 (no `/projects` builder, no scoped curation UI). Listed in [GLOSSARY.md](./GLOSSARY.md) as a roadmap concept; planned for v1.2. |
| **Setup wizard (ongoing)** | Native CP wizard ships at `/control-plane/setup` (hub) and `/control-plane/setup/session/[id]` (5-step wizard: template → connector families → initial admin → preview → launch). Backed by `/api/onboarding/*`. Rewrite to legacy `/admin/setup/*` removed and `(dash)/admin/setup` deleted (Phase 2.1.5). | Single-shot `/bootstrap` remains the entrypoint when no domains exist yet; the wizard runs after that for ongoing template-driven setups. |
| **Control Plane native builders** | **Roles, Scenarios, Presets, Setup wizard, Governance queues × 6, Effective-access, Job-runs list** ship natively under `/control-plane/*` (Phases 2.1.1–2.1.6, 2.1.x — middleware rewrites removed for each, legacy `(dash)/admin/{roles,scenarios,presets,setup}` deleted). **Jobs detail** intentionally renders the product `/jobs/[id]` UI under the CP URL via the single remaining `middleware.ts` rewrite — operator and builder share the same view. | Phase 4 of [ADMIN_UI_CONSOLIDATION_PLAN.md](./ADMIN_UI_CONSOLIDATION_PLAN.md) is effectively complete except for the intentional Jobs-detail share. |
| **Control Plane governance queues** | All six native (Phase 2.1.x): Reviews, Approvals, Stale, Failed jobs, Failed syncs, Policy exceptions. Queue rows are read-only; bulk actions (approve / dismiss / retry) live in dedicated mutation routes and are not yet auto-wired into the CP queue UI | The `/governance` product page (1006 lines) remains the place for inline approve/reject/feedback flows on individual items. |
| **Effective-access UI** | `/control-plane/users/[id]/access` is a stub | "Inspect effective access" view (9-step pipeline trace from [`identity_access/access.go`](../apps/api/internal/identity_access/access.go)) is Phase 2. |
| **Connector webhooks** | **Slack** (Events API, HMAC-SHA256, replay window, URL-verification challenge, dedup via `event_id`) and **Mattermost** (Outgoing Webhooks, shared-token auth, dedup via `post_id`) ship native webhook handlers. Other 16 adapters remain polling-only | Endpoint: `POST /connectors/webhook/:adapter_kind/:source_feed_id`. Per-feed secrets live in `connector_config_json` (`signing_secret` for Slack, `outgoing_webhook_token` for Mattermost). Test fixtures in [`adapters/slack/webhook_test.go`](../apps/api/internal/ingestion_connectors/adapters/slack/webhook_test.go) and [`adapters/mattermost/webhook_test.go`](../apps/api/internal/ingestion_connectors/adapters/mattermost/webhook_test.go) show the verification schemes; no live workspace required. Other connector families opt in by implementing the same `WebhookHandler` interface and surfacing sentinel errors through the central route's status mapping. |
| **AI summarize / governance follow-up tasks** | Removed in Phase 1 alignment | `TaskAISummarize` and `TaskGovernanceFollowUp` were silent-success stubs in `cmd/connectorworker`; both task types and their payload structs were deleted. Not planned for v1. |
| **AI Privacy Vault auditability** | `vault.placeholder_stored`, `vault.placeholder_decrypted`, and `vault.rehydration_applied` events appear in `audit_events` (Phase 1 hardening) | Tokenizer-only rehydration (in-memory, no vault) is **not** audited because the cleartext never crosses the request lifecycle; vault-backed flows always emit the trio. |
| **GraphRAG permission filter** | Phase 1 hardening: graph-expanded chunks pass through the same canView callback as seed entities | Without Neo4j (`NEO4J_URL` unset) the expansion is skipped entirely; with Neo4j the expanded set is filtered before reaching synthesis context. |
| **Multi-tenant deployment** | **Out of scope by design** ([ADR-0014](./adr/0014-single-tenant-deployment-stance.md)) | Knowledge Layer is single-tenant: one instance per organization. To host multiple unrelated organizations, deploy multiple Knowledge Layer instances, each with its own Postgres + Redis. There is no `tenant_id` column, no tenant routing, no shared-cluster isolation primitives. Domains are an *intra-organization* partition, not a tenancy primitive. |

When shipping features, update this table if behavior crosses from stub to supported.
